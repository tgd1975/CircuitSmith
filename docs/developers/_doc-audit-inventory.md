## Method

The repo holds **292 tracked `.md` files**. The overwhelming majority are
*records* (task/idea files), *immutable decisions* (ADRs), *generated
indexes*, *generated artefact sidecars*, or *structured skill definitions*
— none of which carry a hand-written "voice" that can drift. Inventorying
all 292 individually would bury the ~51 files the audit actually targets.

So this inventory **buckets the non-prose classes wholesale** (§1, with a
rationale for excluding each from voice-rewrite scope) and **enumerates the
prose docs individually** (§2). Freshness is judged by *content* against the
shipped reality (CircuitSmith is a published `circuitsmith` package at
v0.1.0, code under `src/circuitsmith/`), not by git-blame date — per the
task's "override with judgment" clause, content is the load-bearing signal.
The `Era` column gives the epic that produced or last reshaped the file in
lieu of a per-file `git blame` (kept cheap deliberately; exact dates are a
`git log -1 -- <file>` away if a specific file needs adjudicating).

Audience values: `builder`, `developer`, `contributor`, `user`, `mixed`.
Freshness values: `pre-epic-001`, `mid-epic` (EPIC-001..005), `epic-006`,
`post-epic-006`.

## §3 — Orphans and duplicate-coverage

**Orphan analysis is deferred to TASK-105's `check_doc_references.py`**,
which builds the actual inbound-link graph; a hand pass can't be
authoritative across 292 files. Preliminary *candidates* (docs not obviously
linked from any index or sibling): `MERMAID_STYLE_GUIDE.md`,
`BRANCH_PROTECTION_CONCEPT.md`, `docs/builders/wiring/*/README.md`. Confirm
or clear these when TASK-105's script lands.

**Duplicate-coverage (load-bearing finding):**

1. **`docs/developers/TESTING.md` ↔ `docs/developers/testing/` (EPIC-011).**
   The single-file `TESTING.md` predates and overlaps the new test-plan
   directory. It also carries stale `from circuit.*` imports. **TASK-107**
   should reconcile: trim `TESTING.md` to an intro that points at
   `testing/README.md` as canonical, or fold its unique content in.
2. **ERC-check documentation** appears in
   `.claude/skills/circuit/docs/erc-checks.md` (human reference),
   `docs/developers/testing/erc-engine.md` (test plan),
   `src/circuitsmith/knowledge/rules.json` (machine source), and the
   archived `idea-001.erc-engine.md` (dossier). This layering is
   **intentional** (different audiences/roles); `rules.json` is
   authoritative. No collapse needed — noted so TASK-104 doesn't "unify"
   them by mistake.
3. **"Concept stage" claim** is repeated across `README.md`,
   `ARCHITECTURE.md`, `CONTRIBUTING.md`, `CLAUDE.md`, `TESTING.md` — this
   is a *drift cluster*, not genuine duplicate coverage. Catalogued in
   TASK-103.
